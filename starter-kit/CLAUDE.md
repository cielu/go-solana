## 1. Identity

- **Project**: `github.com/cielu/solana-go`
- **License**: Apache-2.0
- **Minimum Go version**: 1.22
- **Pre-1.0**: API is unstable. Every tag below `v1.0.0` is allowed to break.
- **Primary maintainer**: @cielu

## 2. North Star

Build the **fastest, cleanest, most honestly-documented** Solana client in Go.

The direct competitor is [`gagliardetto/solana-go`](https://github.com/gagliardetto/solana-go)
— the de-facto standard. We intentionally picked the same repository name
(`solana-go`) to make the positioning unambiguous: same slot in the ecosystem,
better implementation.

## 3. Goals (what 1.0 must deliver)

1. **Performance leader**, provably. Every performance claim in README.md and
   CLAIMS.md must be backed by a checked-in benchmark, not vibes.
2. **API that is a pleasure to use**: typed functional options everywhere, no
   `...interface{}`, error wrapping with method context, `context.Context`
   plumbed through every public entry point.
3. **Zero library-code panics**. A library must never terminate the caller's
   process. All "impossible" states return errors.
4. **IDL code generator** (`cmd/anchoridl-gen/`) so new Anchor programs can be
   bound in minutes, not days. This is the ecosystem moat.
5. **High-level helpers** that the old libraries only half-provide:
   `SendAndConfirmTransaction` with automatic blockhash refresh, priority-fee
   estimation, transaction simulation with decoded errors.
6. **>80% test coverage** on the core types (keys, message, transaction,
   binary encoding) and >60% everywhere else.
7. **Benchmark suite with checked-in fixtures** so any contributor can run
   `go test -bench=. ./...` and get numbers comparable to the README.

## 4. Non-goals

- **Bundling DeFi protocol bindings in the main repo.** Whirlpool, Raydium,
  Jupiter, Serum, Metaplex, etc. live in a separate repository
  (`cielu/solana-programs` or similar), generated by `anchoridl-gen`. The main
  repo stays small and focused.
- **Feature parity with `gagliardetto/solana-go` on day one**. We ship fewer
  features done better, and catch up over time.
- **Supporting Go versions older than 1.22.** If you feel the need to write a
  `//go:build go1.21` fallback, stop.
- **Vendored go-ethereum code.** The old `cielu/go-solana` copied `rpc/` from
  geth, which is LGPL. We write our own RPC transport, or use a MIT/Apache2
  library. No LGPL code in this repository, ever.
- **Reflection-heavy decoding paths.** If you find yourself reaching for
  `reflect` in a hot path, stop and think.

## 5. Architectural principles (non-negotiable)

These are **binding**. If a pull request violates any of them, reject it or
rewrite it before merging.

1. **No `...interface{}` variadics for typed arguments.** Use functional
   options (`type XxxOption func(*xxxConfig)`).
2. **No `panic` in library code.** The only exceptions are `init()` and
   genuine programmer errors in test helpers.
3. **No silent argument-dropping.** If the user passes something we can't
   honor, return an error that names the offending value.
4. **Errors are wrapped with method context.** A typical error reads
   `"solana rpc getBalance: ..."`, not a bare `"Forbidden"`.
5. **`context.Context` is the first argument of every public method that
   performs I/O.** No exceptions.
6. **Public map returns are defensive copies.** Callers cannot mutate
   internal state by writing to a returned map.
7. **No `*big.Int` in hot paths.** Lamport amounts are `uint64`; if you think
   you need a bigger integer, you're probably wrong, and if you're right it
   deserves a dedicated type with a comment.
8. **`encoding/json` is banned from request/response decoding paths.** Use
   a faster JSON library (`go-json` or `jsoniter`) with a compatibility
   shim. `encoding/json` is fine for tests and tooling.
9. **Every exported type has a doc comment** naming the RPC method or
   protocol concept it represents.
10. **Every performance-sensitive function has a benchmark.** `sync.Pool`
    use must be justified by a benchmark showing the win.

## 6. Tech stack decisions

| Area | Choice | Rationale |
|---|---|---|
| Go version | 1.22 | `slices`, `maps`, `cmp`, PGO, `for range int` |
| JSON | `github.com/goccy/go-json` (TBD, benchmark vs jsoniter first) | 5-10x faster than `encoding/json` for our shapes |
| Binary encoding | Custom `internal/binary`, zero-copy where possible | Avoid reflect, avoid allocations |
| Base58 | `github.com/mr-tron/base58` | Battle-tested, no better option |
| Ed25519 | `crypto/ed25519` stdlib | No reason to vendor |
| HTTP client | `net/http` stdlib + option to inject | No `resty`/`fasthttp` dependency |
| WebSocket | `github.com/gorilla/websocket` | The default in the ecosystem |
| HD wallet / mnemonic | `github.com/tyler-smith/go-bip39` + small SLIP-0010 in-tree | Proven libs |
| Testing | stdlib + `testify/require` (no DSL frameworks) | Low magic, low churn |
| Benchmarks | stdlib `testing.B`, no external runner | Simplicity |
| CI | GitHub Actions | Free, universal |
| License | Apache-2.0 | Ecosystem default, patent grant |

## 8. Commit style

- Imperative, lowercase, no trailing period. `fix binary decoder off-by-one`.
- One logical change per commit. Architectural cleanups go in their own
  commits even if they touch many files.
- Every commit must leave `go build ./...`, `go vet ./...`, and
  `go test ./...` green.
- Breaking changes get a `BREAKING CHANGE:` footer in the commit body.

## 9. How to run things

```bash
# Build everything
go build ./...

# Lint
go vet ./...

# Unit tests
go test ./...

# Race detector
go test -race ./...

# Benchmarks (compare against baseline in CLAIMS.md)
go test -run=^$ -bench=. -benchmem ./...

# Single benchmark against gagliardetto's equivalent
go test -run=^$ -bench=BenchmarkTransaction_Marshal -benchmem ./benchmarks/...

# Regenerate a program binding from its IDL
go run ./cmd/anchoridl-gen -idl idl/foo.json -out programs/foo
```

## 11. Things you must not do

- **Do not copy code from `gagliardetto/solana-go`**. Their code is
  Apache-2.0 so it's technically legal, but we want a clean-room
  implementation so we can diverge freely and so that every design
  choice is intentional. If you need to know *how* something is done,
  read the Solana docs first, their code second, and write your own.
- **Do not copy LGPL code from `cielu/go-solana/rpc/`** (it was vendored
  from go-ethereum). We need our own JSON-RPC transport. This is the
  whole reason we're starting fresh.
- **Do not add a dependency without benchmark or architectural
  justification.** Every dependency is a long-term maintenance cost.
- **Do not introduce a test that requires network access** unless it is
  guarded by a build tag (`//go:build integration`) and clearly
  documented. Unit tests must run offline.
- **Do not claim a performance number in the README** unless it comes
  from a checked-in benchmark that CI runs on every push.
- **Do not merge to `main` with a failing CI**.

## 12. When in doubt

1. Check `ROADMAP.md` for the current phase goals.
2. Check `CLAIMS.md` to see what we've committed to publicly.
3. If the answer is still unclear, write an ADR (Architectural Decision
   Record) under `docs/design/NNNN-title.md` and link it from this file
   under §6 or §11.
4. When in real doubt, do less. Half a clean feature is better than a
   full messy one.
